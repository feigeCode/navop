# 设置侧边栏滚动定位修复设计

## 目标

点击设置页左侧的设置分组后，右侧对应设置块的顶部应稳定对齐到内容列表可视区域顶部，也就是固定标题栏下方。

## 问题与根因

设置侧边栏点击分组后会记录目标分组索引，设置页面下一次渲染时调用 `ListState::scroll_to_reveal_item`。该方法只保证目标列表项进入可视区域，不保证目标项顶部对齐。设置块高度差异较大时，目标块可能只露出一部分，用户因此无法明确判断是否定位到所选分组。

## 方案

保留现有的延迟滚动数据流和分组索引计算，只把列表消费目标索引时的滚动策略改为显式顶部定位：

1. 左侧分组点击后继续写入 `deferred_scroll_group_ix`。
2. 右侧设置页面渲染时继续读取并清空该索引。
3. 使用 `ListState::scroll_to(ListOffset { item_ix: group_ix, offset_in_item: px(0.) })`，让目标设置块顶部对齐到列表可视区域顶部。
4. 页面标题栏位于列表外部，因此保持固定，不参与滚动坐标计算。

不引入元素坐标测量、额外滚动偏移或编辑器相关逻辑。

## 搜索与边界行为

- 搜索过滤时，侧边栏与右侧列表继续基于同一份过滤后的页面和分组顺序，目标索引保持一致。
- 点击页面标题时只切换页面，不强制滚动到某个分组。
- 点击当前已可见的分组时仍执行顶部对齐，保证行为确定。
- 最后一个设置块受列表最大滚动范围限制时，以列表允许的最大位置为准。

## 测试与验证

- 增加针对设置分组导航滚动目标的回归测试，验证目标索引不变且项内偏移为零。
- 运行 `ui` crate 中与设置组件相关的定向测试。
- 运行 `cargo check -p main`，确认主应用调用链可编译。
- 运行 `git diff --check`，确认没有空白错误。
- 手工打开设置页，分别点击靠前、中间和靠后的分组，确认目标块顶部对齐到标题栏下方。
