# 远端写操作完成后统一刷新侧边栏设计

## 目标

任何成功改变远端文件系统内容或 metadata 的操作完成后，统一刷新 SFTP 当前可见远端目录；不自动切换用户当前路径。

## 范围

刷新触发源包括外部编辑器上传、冲突覆盖、内置远程编辑器保存，以及 SFTP 新建、删除、重命名、移动、上传、粘贴和冲突覆盖。下载、预览、搜索、复制路径等只读操作不触发刷新。

## 架构

`remote_file_editor` 不依赖 `sftp_view`。打开内置或外部编辑器时，由调用方传入类型擦除的 `RemoteMutationCallback`。回调接收 GPUI window/app context，内部捕获 SFTP View 的 `WeakEntity` 并调用统一的当前目录刷新入口。

远端写入只有在 SFTP write/rename/remove 等操作真正成功后才触发回调。刷新失败不改变原操作成功结果。批量操作保留批次完成后刷新一次的语义，不对每个文件重复刷新。

## 验收标准

- 外部编辑器自动上传成功后当前远端目录刷新。
- 外部冲突覆盖成功后刷新。
- 内置远程编辑器保存成功后刷新。
- SFTP 自身远端写操作使用统一刷新辅助入口。
- 失败或取消操作不刷新。
- 只读操作不刷新。
- 刷新不改变 `remote_current_path`。
- `remote_file_editor` 与 `sftp_view` 不形成循环依赖。
