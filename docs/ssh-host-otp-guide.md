# SSH 主机的一次性验证码（OTP/TOTP）与提权密码

适用于服务器在 SSH 登录时要求「验证码 / 动态口令」的场景（`Verification code:`、`[sudo] password for xxx:` 这类提示）。配好之后登录由 navop 自动带码，不再弹输入框。

## 1. 先拿到密钥

一次性验证码密钥（TOTP secret）只能由服务器侧生成，navop 不参与生成。常见的三种来源：

| 来源 | 形态 | 说明 |
| --- | --- | --- |
| 服务器管理员 | `otpauth://totp/...?secret=...` 链接 | 最方便，直接粘贴 |
| 服务器上的 `~/.google_authenticator` 第一行 | base32 密钥，如 `JBSWY3DPEHPK3PXP` | 已在用的机器可以直接取 |
| 服务商 / 管理后台 | 二维码图片 | 保存成图片文件，或用截图复制到剪贴板 |

服务器侧通常是 `pam_google_authenticator`（也有用 `pam_oath`、硬件令牌的），由管理员在 `/etc/pam.d/sshd` 与 `sshd_config` 里启用；本仓库的 `script/docker-ssh-test/` 提供了一个可以直接拿来试的完整环境。

## 2. 在 navop 里配置

1. 打开「编辑主机 → **高级选项**」；
2. 勾上「双因素认证」（`Keyboard-Interactive`）——验证码是通过这条通道提交的，关掉它 navop 就不会自动带码；
3. 在「一次性验证码密钥」里填密钥，三种方式任选：
   - 直接粘贴 `otpauth://` 链接或 base32 密钥；
   - 点「扫描二维码图片」，选一张二维码图片文件；
   - 把二维码图片复制到剪贴板后点「粘贴图片」；
4. 填对后下方会出现摘要和实时验证码，例如 `6 位 · 30 秒 · SHA1 · 当前验证码 123456（剩余 18 秒）`——看到这行就说明解析成功；
5. 点「测试连接」通过后保存。测试连接同样会走自动带码，不需要手工输验证码。

密钥和已保存的密码一样随连接保存（连接参数里的敏感字段统一加密），重装/换机后同步过去也不需要重新扫。

## 3. 顺带自动填 su / sudo 密码

同一页下面还有：

- 「自动填入 su/sudo 密码」：执行 `su`、`sudo` 提示 `Password:` 时自动提交密码。默认跟着登录方式走——密码登录默认开启（服务器本来就知道这个密码），密钥/Agent 登录默认关闭（避免把密码交给远端伪造的提示）；
- 「提权密码」：留空则使用登录密码；root 密码与登录密码不同时才需要单独填。

生效范围与保护：只在刚看到 `sudo`/`su` 命令回显后的短时间内应答；远端提示密码错误、或同一条提示紧接着重复出现时立刻停手交还给你，不会反复重试；单次会话最多自动应答 32 次，够日常折腾，又不至于误判后无限灌密码。

## 4. 常见提示与处理

| 界面提示 | 原因 |
| --- | --- |
| 只接受 otpauth:// 链接 | 粘贴的是别的 scheme（如 `otpauth-migration://`、普通网址） |
| 不支持 HOTP | 服务器给的是计数器型密钥，目前只支持时间型（TOTP） |
| base32 密钥不合法 | 密钥里有非 base32 字符，或复制时丢了字符 |
| 位数 / 周期超出范围 | `digits` 需 6–8，`period` 需 1–3600 秒 |
| 图里没找到二维码 | 图片太小、模糊或不是二维码 |
| 二维码不是 TOTP 密钥 | 扫到的是别的二维码（网址、Wi-Fi 等） |
| 请在上方启用双因素认证 | 填了密钥但没开 `Keyboard-Interactive` |
| 密钥有误，请先修正再保存 | 输入框内容解析失败，先修好再保存 |

## 5. 本地验证一套完整流程

仓库内自带一个可复现的测试服务器（OpenSSH + `pam_google_authenticator`，只允许 keyboard-interactive，附带 sudo/su 提权）：

```bash
cd script/docker-ssh-test && docker compose up -d   # 监听 127.0.0.1:2222
./verify.sh                                         # 用 ssh + expect 验证服务器本身
```

| 项 | 值 |
| --- | --- |
| 用户 / 密码 | `tester` / `tester-pass` |
| root 密码（`su root`） | `tester-pass` |
| OTP 密钥 | `JBSWY3DPEHPK3PXP` |

在 navop 里建一条 `127.0.0.1:2222` 的主机，按上面第 2 步填密钥、第 3 步勾提权密码，即可全自动登录并 `sudo`/`su`。无人值守的回归用例：`NAVOP_SSH_E2E=1 cargo test -p terminal --lib docker_ssh -- --ignored`。

## 6. 边界与安全

- 验证码由客户端本地按 TOTP 生成，密钥不会因为登录被发到远端；远端只看到那 6 位数字；
- 自动应答只对「含验证码提示」的 keyboard-interactive 请求生效；遇到其它类型的质询（如设备二次确认、短信码）仍然弹窗让你手工输入；
- 服务器的 `pam_google_authenticator` 默认禁止同一时间窗的验证码复用，所以 30 秒内连续新开多条连接时，第二条可能认证失败一次，等下一窗口或重连即可；
- 提权密码自动填入有冷却与次数上限，密码错误时只试一次就停手。
