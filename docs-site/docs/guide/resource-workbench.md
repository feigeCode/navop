# 原生资源工作台

原生资源工作台（Native Resource Workbench）是 Navop 为扩展提供的一类原生界面：扩展在 manifest 中声明资源、集合、表格、详情页和操作，宿主用原生 GPUI 渲染出可浏览、可操作的工作台，而不需要扩展自带 UI。首个使用该机制发布的是 Docker 扩展。

![扩展市场](/images/extension.png)

## 与普通连接扩展的区别

- 普通连接扩展通常只提供连接表单和一个自定义页面。
- 资源工作台由宿主统一渲染导航、集合表格、详情页和操作按钮，扩展只声明数据路径与操作方法，因此外观、排序、分页和交互跟随 Navop 主题与设计系统。
- 各操作按 effect 分为只读（read）、写入（write）和破坏性（destructive）：破坏性操作在执行前会弹出确认。

## Docker 工作台

安装 Docker 扩展后，新建 Docker 连接并填写本机 socket（默认 `unix://~/.docker/run/docker.sock`，也可用 `unix:///var/run/docker.sock`）。工作台提供：

- 引擎概览：容器、镜像、磁盘与运行时资源用量。
- 容器：列表浏览，启动、停止、重启和删除，查看进程与文件系统变更。
- 镜像：镜像列表与异步拉取。
- 日志：容器日志查看器，支持 tail 行数控制。
- 终端：进入容器执行命令的 exec 终端。

删除容器、停止运行中的服务等操作会影响真实环境，执行前请确认目标容器与影响范围。

## 权限与自动化

工作台操作通过扩展 provider 进程执行，并受扩展声明的权限约束（例如访问 `docker.sock`）。在 Public MCP 等自动化通道中，默认只暴露只读操作；写入和破坏性操作仍需人工确认，不会静默放通。

## 排查顺序

1. 确认 Docker 守护进程正在运行，且 socket 路径正确。
2. 连接失败时检查当前用户是否有权限访问 `docker.sock`。
3. 操作按钮长时间无响应时，检查扩展 provider 进程是否存活；进程崩溃后宿主会自动重启并尝试恢复连接。
4. 单个扩展损坏不会影响其他扩展，可在扩展管理页重新加载或卸载后重装。
