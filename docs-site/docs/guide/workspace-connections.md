# 首页、工作区与连接管理

首页是所有资源的统一入口。连接可以按工作区分组，并以卡片或列表呈现；搜索、排序和快速打开帮助你在大量数据库与服务器之间切换，而不会改变真实远端资源。

## 浏览首页与工作区

使用顶部搜索框按名称查找连接，在卡片视图和列表视图之间切换。工作区可用于区分生产、测试、本地、客户或项目环境；创建工作区后，可以编辑名称、调整顺序、筛选连接，或将连接放入更合适的工作区。

删除工作区前检查其中的连接如何处理。工作区是组织层，不代表远端数据库或服务器本身，但删除或移动操作仍可能影响本地入口和同步状态。给生产连接使用明显名称和颜色，避免在相似主机之间误操作。

## 新建与编辑连接

点击“新建连接”后，可以选择数据库、Redis、MongoDB、SSH/SFTP、本地 Terminal、RDP、VNC、Serial、Port Forwarding，或扩展提供的更多类型。填写基本信息、认证方式和高级选项后，先测试连接再保存。不同类型的完整字段在后续章节说明。

已有连接可以编辑、复制和删除。复制适合创建同一服务器上的不同数据库或环境，但复制后必须修改名称、目标和凭据，避免两个卡片看似不同却连接到同一生产资源。连接正在被标签页、终端、转发或传输任务使用时，应先关闭相关会话，再编辑或删除。

## 搜索、快速打开与日常整理

名称搜索只影响当前显示，不会修改连接。卡片适合识别少量常用资源，列表适合密集浏览和排序。进入连接后产生的数据库编辑器、终端或文件标签可独立关闭；关闭标签不等于删除保存的连接。

建议定期清理失效连接、统一命名并检查工作区归属。不要在连接名称中写密码或 Token。共享屏幕或提交截图时，主机名、用户名、数据库名和内网地址也可能是敏感信息，应先脱敏。

## 从其他应用导入

“从其他应用导入”依赖连接导入扩展。加载扩展后，可扫描受支持的本地应用来源，或选择导出的连接文件。Navop 会先展示预览结果，列出数据库和 SSH 记录，并标识密码已导入、密码缺失、来源不支持或权限被拒绝等状态；确认勾选后才保存。

导入过程会检测重复项并跳过明显重复记录，但仍应人工核对名称、主机、端口、数据库和认证方式。部分来源无法导出密码，需要在保存后重新输入。当前端口转发记录的导入保存与重复检测可能不受支持，应手动重建并测试。

## 删除、同步与风险边界

删除连接只应在确认没有活动使用后进行。若启用了个人或团队同步，本地删除可能转化为需要解决的同步变更；另一设备同时编辑时，可能出现本地与远端冲突。解决冲突前比较更新时间和字段，不要默认以任一侧覆盖。

连接配置与远端数据是两回事：删除 Navop 中的连接一般不会删除服务器或数据库，但在连接工作区内执行的 SQL、Key 删除、文件覆盖等操作会真实影响远端。管理入口时保持这一边界，所有高风险数据操作仍按对应章节的安全步骤执行。
