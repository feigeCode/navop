# SSH 端口转发

端口转发通过已保存的 SSH/SFTP 连接建立网络通道。Navop 支持本地转发和动态 SOCKS 转发，并显示运行状态与活动日志。转发只提供网络路径，不会自动增加目标服务权限或加密应用层协议。

## 选择 SSH 基础连接

新建 Port Forwarding 时先选择可用的 SSH/SFTP 连接。该连接负责跳板机地址、认证、代理和主机验证；先确保它能独立登录。修改或删除基础 SSH 连接前，应先停止依赖它的转发。

生产跳板机建议使用受限账号、密钥和明确的目标访问规则。转发建立成功只说明通道可用，目标数据库、Web 服务或其他协议仍需自己的认证与 TLS。

## 本地端口转发

本地转发把本机监听地址与端口映射到 SSH 侧可访问的目标地址和端口。绑定 `127.0.0.1` 通常只允许本机访问；绑定所有网卡可能把通道暴露给局域网，必须结合防火墙和业务需要谨慎选择。

目标地址从 SSH 服务器的网络视角解析，不一定等于本机可访问的地址。端口被占用时选择其他监听端口，并同步修改客户端配置。连接应用时使用本地监听地址，但仍按目标服务要求提供账号和证书。

## 动态 SOCKS 转发

动态转发在本地创建 SOCKS 代理，由客户端为每次请求指定目标。配置监听地址和端口后，在浏览器、数据库工具或其他支持 SOCKS 的客户端中显式使用该代理。DNS 是否经代理解析取决于客户端配置，敏感场景应确认没有本地 DNS 泄漏。

不要把动态 SOCKS 监听在不可信网络可访问的地址，也不要将其当作匿名服务。所有流量仍受 SSH 账号、跳板机日志和目标系统策略约束。

## 运行状态与活动日志

启动后查看状态、连接次数和活动日志。失败时区分 SSH 断开、监听端口冲突、目标拒绝、DNS 失败和权限问题；可按提示重试，但持续失败应先修复根因。

活动日志可能包含主机、端口和连接时间，提交问题前需要脱敏。转发流量较大时关注跳板机带宽、连接数和空闲超时。

## 停止与故障影响

停止转发会立即中断所有正在通过该通道通信的连接，包括数据库事务、文件传输和浏览器请求。停止前先关闭或暂停下游客户端，确认没有关键写入。

应用退出、电脑休眠、网络切换或 SSH 重连也可能使转发失效。恢复后下游应用通常需要重新连接；不要假设旧会话会自动续传或保持事务状态。
