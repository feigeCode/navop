# MongoDB Explorer

MongoDB Explorer 用于管理连接、数据库、集合、文档、索引和校验规则，并支持 Find、Aggregate、Count 与 Explain。删除数据库、集合或文档会真实修改服务器数据，应优先使用受限账号和测试环境。

## 连接与安全设置

可以填写连接字符串，或按主机、端口和认证参数配置。根据部署选择认证数据库、超时和 TLS；网络受限时使用 SSH 隧道。副本集或分片集群的连接字符串应包含正确参数，并确保隧道或网络能访问驱动最终选择的节点。

测试连接后再保存。TLS 生产连接应验证证书，密码与证书私钥不得写入公开文档。连接超时可能来自 DNS、节点发现、防火墙、认证源或服务器选择，不要只提高超时掩盖根因。

## 数据库、集合与文档浏览

展开数据库和集合后，使用 JSON 过滤条件查询文档，并设置排序与分页。过滤器必须是有效 JSON/扩展 JSON，字段类型要与实际 BSON 类型匹配。当前页搜索与服务器查询含义不同，精确结果应依赖过滤条件。

可以创建和删除数据库或集合。MongoDB 某些对象只在写入后真正出现；删除数据库或集合不可恢复，操作前必须核对连接、名称和备份。

## 文档新增、编辑与删除

文档以 JSON 形式查看和编辑。新增时注意 `_id`、日期、ObjectId、数组和嵌套对象的类型；把特殊 BSON 类型误写成普通字符串会改变语义。修改前读取最新版本，避免覆盖其他客户端的并发更新。

删除文档前使用同一过滤条件执行 Find 或 Count，确认匹配数量。批量写入应从小范围开始，并在完成后重新查询关键文档。格式正确不代表满足应用业务规则。

## Find、Aggregate 与 Count

Find 适合条件查询、投影、排序和分页；Count 用于确认匹配规模；Aggregate 通过管道完成分组、转换、联表和统计。复杂 Aggregate 先逐阶段验证，每增加一个 stage 都检查输出结构和数据量。

查询可能缺少索引并占用大量资源。不要在生产高峰直接执行未知来源的全集合扫描或大规模聚合；先加限制条件，观察执行计划和服务器负载。

## 索引、校验规则与 Explain

索引页面用于查看、新建和删除索引。创建唯一索引前清理重复数据；删除索引前确认没有关键查询依赖。大型集合建索引会消耗 CPU、内存和磁盘，并可能影响业务延迟。

校验规则定义文档写入约束，修改后可能让现有或后续写入失败。先在样本集合验证 JSON Schema 或表达式。Explain 可展示查询或聚合的执行计划，重点检查扫描文档数、返回数和索引使用情况，再决定是否调整索引或查询。
