# 表数据浏览与编辑

表数据页用于分页查看、筛选、复制和修改记录。预览中的行不是静态截图：提交新增、编辑或删除后会真实写入数据库，因此必须确认主键、过滤条件和当前环境。

![数据库数据工作区](/images/database.png)

## 浏览、分页与筛选

从表或视图打开数据页，使用分页控制加载规模，并在当前页搜索可见内容。当前页搜索只过滤已经加载的数据，不等同于服务器端完整查询；需要精确筛选或跨页统计时使用 SQL 编辑器。

刷新会重新读取服务器状态。数据量较大时保持合理页大小和最大行数，避免长时间锁定界面。视图是否可编辑取决于数据库及视图定义，不能编辑时应回到基础表或编写显式 SQL。

## 编辑单元格与特殊值

双击或进入编辑状态修改单元格；长文本、JSON 或多行内容可使用大文本编辑器。`NULL` 与空字符串含义不同：`NULL` 表示缺失值，空字符串是长度为零的文本。不要用空白输入猜测最终写入结果，应使用明确的 NULL 操作。

新增记录可按列填写，也可克隆现有行后修改。需要唯一标识时可以生成 UUID，但仍要满足字段类型、主键和业务约束。二进制、大对象、自动生成列或数据库特有类型可能受驱动限制，提交后应刷新并核对实际值。

## 新增、克隆与删除行

新增行会在本地变更集中等待提交；克隆行适合复用大部分字段，但必须修改主键和唯一列。删除行前确认选中数量和主键，尤其是在排序、分页或筛选状态下。没有可靠主键的表可能无法安全定位单行。

多项编辑可以一起预览。若发现目标错误，先撤销本地变更，不要提交后再尝试人工恢复。生产数据删除应优先通过受控 SQL、事务和备份完成。

## SQL 预览与提交

提交前打开 SQL 预览，检查 Navop 将生成的 INSERT、UPDATE 和 DELETE，包括表名、列、值和定位条件。SQL 预览是最后一道人工确认，不保证业务逻辑正确。确认无误后提交；失败时查看具体语句和约束错误，避免重复提交已成功的部分。

涉及多行时了解当前驱动的事务行为。提交完成后刷新数据，并用主键或业务条件重新查询验证。审计严格的系统还应在业务变更单中记录执行时间和影响行数。

## 复制与导出结果

单元格、行或结果集可以按支持的格式复制。导出支持 `.xlsx`、`.csv` 和 `.sql`，适合进一步分析、交换或生成插入脚本。导出前确认列范围、行范围、编码、日期和 NULL 表示方式；表格软件可能自动转换长数字或日期。

导出文件可能包含敏感数据，应保存到受控目录并按组织策略加密或删除。需要完整大数据集时优先使用数据库导出工具或分批处理，而不是依赖当前页复制。

## 一次编辑的完整流程

1. 从正确的数据库和 Schema 打开表。
2. 先使用分页、筛选或 SQL 确认目标范围。
3. 双击需要修改的单元格，长文本和 JSON 使用大文本编辑器。
4. 检查 `NULL`、空字符串、数字精度、时间和自动生成字段。
5. 打开 SQL 预览，确认表名、列名、值和定位条件。
6. 提交后刷新，并用主键或业务条件重新查询确认实际结果。

如果一次编辑包含多行，先记录受影响行数，再决定是否提交。筛选条件只影响当前界面显示，不会替你生成业务上正确的 `WHERE` 条件。

## 特殊值检查

| 数据情况 | 建议操作 |
| --- | --- |
| `NULL` | 使用明确的 NULL 操作，不要用空白输入代替 |
| 空字符串 | 确认业务是否允许空文本 |
| UUID/主键 | 克隆行后必须修改唯一字段 |
| JSON | 在大文本编辑器中检查完整结构和转义 |
| 二进制/大对象 | 确认驱动支持和传输大小，不要只看截断预览 |
| 自动生成列 | 不要手动覆盖数据库默认值，除非明确知道后果 |

## 删除行前的双重确认

删除前同时确认筛选条件和主键。排序、分页或刷新后，视觉上的行位置可能改变；不要用“第几行”作为删除依据。生产数据删除应优先使用可审阅、可回滚的 SQL 和备份策略。
