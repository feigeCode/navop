# 数据库导入、导出与 SQL 文件

数据传输工具用于把分隔文本导入表、导出表或查询结果、生成 SQL dump，以及运行已有 SQL 文件。传输前先确认源格式、目标表、编码、事务策略和可恢复方案。

## 导入 CSV 与分隔文本

选择目标表和文件后，设置字符编码、字段分隔符、文本包围符、转义规则以及是否包含标题行。预览列映射，确认文件列与数据库列的顺序、类型和可空性。日期、小数、布尔值、NULL 与空字符串在不同系统中的表示可能不同，应先用少量样本验证。

启用事务可以在支持的数据库中把批量导入作为一个整体处理；“遇错停止”适合要求一致性的任务，“遇错继续”适合收集坏行但必须在结束后检查错误明细。超大文件应分批，并关注数据库日志、磁盘和连接超时。

## 清表与覆盖风险

“导入前清表”会在写入新数据前清除目标表内容，通常不可恢复。只有在已经确认备份、目标环境、外键依赖和恢复步骤后才能启用。测试预览不应勾选该选项，生产环境更应通过变更流程审批。

导入失败不代表目标表完全未变化：具体结果取决于事务支持、提交批次和错误策略。失败后先查询目标行数和关键记录，再决定重试；不要直接重复导入造成重复数据。

## 导出表与查询结果

可以从表或 SQL 结果导出数据。选择列、行范围和目标格式后，检查编码、换行、分隔符、标题行、NULL 表示和日期格式。`.csv` 适合通用交换，`.xlsx` 适合人工查看，`.sql` 适合生成可审阅的插入语句。

表格软件可能把长整数、账号编号或时间自动转换，重要数据应以文本格式复核。导出文件会离开数据库权限边界，包含敏感信息时应存放在受控位置，并在使用后按策略删除。

## SQL dump 与结构数据组合

SQL dump 可以导出结构、数据，或结构和数据。只导结构适合迁移对象定义，只导数据适合已有兼容结构的目标库；组合导出仍需考虑对象创建顺序、外键、触发器、序列和数据库方言。

生成后先检查文件头、目标数据库、字符集和危险语句，再在空白测试库恢复。跨数据库产品迁移不能假设 SQL dump 直接兼容，应使用比较工具或人工转换类型与语法。

## 运行 SQL 文件

选择“运行 SQL 文件”后，确认连接、默认数据库或 Schema、文件编码和执行策略。大型脚本开始前先阅读前几段与结尾，检查是否包含 DROP、TRUNCATE、权限变更或环境专用语句。

根据任务选择事务和遇错停止策略。执行日志用于定位具体失败位置；中途取消或连接断开时，重新确认已提交范围。不要仅凭进度条判断恢复成功，应检查对象数量、关键行数和业务校验结果。
