# 扩展市场与本地扩展

扩展为 Navop 增加数据库驱动、中间件、原生资源工作台、ACP Agent、连接导入、远程桌面 Provider 和语言包等能力。复合扩展还可以在终端或数据库侧栏中声明面板，并向内置 Agent 提供工具。扩展代码在本机运行，应像安装桌面软件一样审查来源、权限、平台与版本兼容性。

![扩展市场](/images/extension.png)

## 浏览市场与扩展类型

从扩展市场按类型或名称查找组件，也可使用「有更新」过滤只看有可更新版本的扩展。数据库驱动增加新的连接类型；ACP Agent 接入外部 Agent；连接导入扩展读取其他应用配置；远程桌面扩展提供 RDP/VNC Provider；语言包为编辑器提供多语言语法高亮（单语言插件不再单独提供，新增语言也会打包进语言包）；原生资源工作台扩展（如 Docker）由宿主渲染集合、详情页与操作界面。

市场条目会说明版本、平台和 Navop 兼容范围。某种连接出现在宣传列表中，不代表未安装驱动时即可创建，应先确认相应扩展已启用。

## 官方扩展仓库

第一方扩展在 [navop-extensions](https://github.com/feigeCode/navop-extensions) 仓库独立构建与发布，市场中的官方扩展均来自该仓库。当前目录按类型分组如下：

- **数据库驱动**：TDengine、DuckDB、Redis、MongoDB（4.2+ / 3.6 / 3.2–3.4 三档）、达梦 DM、金仓 KingbaseES、GBase 8s、OceanBase、openGauss、Apache IoTDB、神通 Oscar，以及免 Oracle Instant Client 的纯 Go Oracle 驱动。
- **中间件**：MQTT（订阅、消息、发布等视图，支持 SSH 隧道）、RocketMQ（Topic、订阅组与消息）、Elasticsearch 9（集群概览、索引与文档搜索）。
- **原生资源工作台**：Docker（引擎概览、容器与镜像、卷、网络、日志、进程、统计、文件系统变更、挂载、inspect 与 exec 终端），由宿主原生渲染集合、详情页与操作。
- **复合面板**：服务器日志（底部通栏，按主机记录日志文件，支持 tail、远端过滤、搜索与跟随）、服务器容器（右侧多页签，切换进程、容器、镜像、卷、网络、Compose 与 Kubernetes）。
- **远程桌面 Provider**：RDP、VNC。
- **ACP Agent**：Codex、Claude Code、OpenCode。
- **连接导入**：SecureCRT、Xshell、WindTerm、OpenSSH config、Navicat、DBeaver、JetBrains DataGrip、MongoDB Compass、Redis Desktop、TablePlus。
- **外部编辑器**：Zed、Notepad++、Notepad--。
- **Notes 渲染与导出**：Mermaid 图、LaTeX 数学公式渲染，HTML / PDF / Word 导出。
- **语言包**：基于 Tree-sitter 的多语言语法高亮扩展包。

各扩展的平台支持、最低版本与方法契约以市场条目和仓库文档为准；旧版 MongoDB 等面向 EOL 服务器的驱动不承诺支持 SRV、TLS 等新特性。

## 扩展面板与停靠位置

复合扩展可以在清单的 `contributes.panels` 中声明面板位置：左侧、右侧或底部，默认在右侧。Navop 会按声明把面板放进 SSH 终端侧栏等对应区域；安装后仍可手动拖动面板，手动调整过的位置优先于清单声明，并会按资源记住。

数据库侧栏的底部面板会占满内容区宽度，高度可以拖动调整。侧栏上的「+」会直接打开扩展市场，并只显示可添加为面板的复合扩展，便于快速补齐工作区。当前官方复合扩展示例包括：

- **服务器日志**：底部通栏面板，按主机保存日志文件记录，支持 tail 行数、远端过滤、输出内搜索和跟随刷新。
- **服务器容器**：右侧多页签面板，在进程、Docker 容器、镜像、卷、网络、Compose 与 Kubernetes 之间切换，容器支持查看日志以及启动、停止、重启确认。

面板只是入口，读取和操作仍通过扩展自身的权限执行；在共享服务器上使用前先确认命令影响范围。

## 插件提供的 AI 工具

扩展可以在 `contributes.tools` 中声明工具，供内置 Agent 和外部 MCP 客户端调用。这类工具默认关闭，需要按扩展开关启用；启用后还可以单独禁用某个工具，并受超时、结果大小上限与风险确认约束。

每个插件标签页都有 AI 侧边栏：右侧浮钮打开，默认收起，可以拖动加宽，并把当前插件页面作为上下文。插件工具会真实执行扩展能力，使用前先阅读工具说明、参数和审批内容，不要对生产资源长期放开高风险工具。

## 安装、更新与重载

市场安装前阅读发布者、说明和所需权限。安装完成后按提示重载扩展或重新启动应用；新连接类型和设置项可能只有重载后出现。Navop 会按扩展类型刷新相关能力，并让语言解析器保持按需加载，避免普通扩展变更触发全部语言 WASM 编译。更新前保存工作并阅读变更说明，数据库驱动或 Provider 更新可能改变连接行为。

Navop 启动后会在后台检查扩展市场并与已安装版本对比，发现新版本时弹出通知，可直接跳转到扩展市场查看更新；同一批更新仅提醒一次，确认后不再重复打扰。扩展市场页的「有更新」过滤可只显示可更新扩展。

扩展异常时先尝试禁用、启用或重载，再检查日志和兼容版本。不要在生产任务进行中更新负责当前连接的驱动。

## 本地与离线包

开发者或受限网络环境可以安装本地扩展、离线包。只使用可信来源并核对包完整性；本地安装不会经过市场的全部分发检查。测试扩展应使用非生产数据和独立工作区。语言能力只接受语言包安装：单独的语言扩展包会被拒绝，请改用对应的语言包。

离线环境还需准备扩展自身依赖。复制扩展目录时保留完整清单和资源，不要只移动单个二进制文件。升级 Navop 后重新验证离线扩展兼容性。

## 权限与运行限制

扩展可能访问网络、文件、连接元数据或渲染资源，具体以清单和界面提示为准。只授予功能所需权限，未知发布者不应接触生产凭据。连接导入扩展读取其他应用配置时，系统可能要求额外文件权限；拒绝后部分密码或记录无法导入属于正常结果。

WASM 和其他受控运行时具有资源与超时限制。扩展任务失败时应检查输入、权限、日志和兼容版本，不要通过无限放宽资源限制掩盖问题。

## 卸载与问题报告

卸载前关闭依赖该扩展的连接、ACP 会话和远程桌面。卸载会在后台执行并显示状态；完成前不要重复触发安装、重载或卸载。卸载会移除功能入口，但通常不会删除远端数据；已保存连接可能在重新安装兼容扩展后恢复可用。是否保留扩展设置取决于类型和版本。

报告问题时提供 Navop 版本、扩展名称与版本、平台、重现步骤和脱敏日志。不要提交数据库密码、SSH 私钥、API key、主密钥或完整的连接导入文件。
