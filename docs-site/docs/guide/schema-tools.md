# Schema、表设计与比较同步

结构工具覆盖数据库对象浏览、表设计器、DDL、ER 图、Schema Compare 和 Data Compare。它们可能生成 DROP、ALTER、INSERT、UPDATE 或 DELETE，任何自动计划都必须经过人工审阅。

![ER 图与数据库关系](/images/er.png)

## 浏览数据库对象

连接后按数据库和 Schema 展开表、视图及其他受支持对象。打开表可查看列、类型、默认值、可空性、主键、索引和 DDL。对象列表受账号权限、当前上下文和 Schema 过滤共同影响；导航树中不可见不代表服务器上不存在。

刷新对象树可读取外部变更。多个成员同时修改结构时，不要仅依赖旧标签页中的缓存信息，执行设计变更前重新加载当前定义。

## 使用表设计器

表设计器用于新建或修改列、索引以及数据库支持的引擎、字符集和排序规则。修改字段类型、长度、可空性或默认值前，评估已有数据能否转换；新增唯一索引前先检查重复数据。

切换到 SQL/DDL 预览查看生成语句。Navop 会识别 DROP 等破坏性 SQL 并要求在预览页确认，但风险检测不能理解全部业务影响。复杂迁移应拆分步骤，在测试库验证，并准备回滚或恢复方案。

## ER 图与关系理解

ER 图用于可视化表及其关系，帮助理解现有 Schema、讨论设计和定位依赖。图中的关系主要来自数据库元数据；没有外键约束的逻辑关系不会自动出现，需要结合业务代码判断。

生成大型 ER 图时先选择相关对象，减少视觉噪声。ER 图是结构视图，不是实时数据流或权限模型，不能替代 DDL 审计与数据字典。

## Schema Compare

Schema Compare 比较源连接和目标连接的对象定义，显示新增、修改和缺失差异，并生成同步计划。先确认源与目标方向，避免把旧环境覆盖到新环境。选择需要同步的对象后，逐项检查 DDL、依赖顺序和不支持的数据库特性。

同步 SQL 可以在执行前编辑。任何 DROP、列类型收窄、重建索引或大表 ALTER 都应安排维护窗口，并确认备份与锁影响。跨不同数据库产品比较时，类型映射和语法差异需要额外人工处理。

## Data Compare 与执行计划

Data Compare 按可识别的键比较源表与目标表，统计需要 INSERT、UPDATE 和 DELETE 的记录，并形成同步计划。没有稳定主键或唯一键时，匹配结果可能不可靠；先检查键选择、过滤范围和数据量。

执行前阅读可编辑的同步 SQL，选择是否使用事务以及遇错继续或停止。执行日志会记录进度与失败项，但“成功”仍应通过目标查询验证。大规模同步先在样本或副本上演练，避免长事务、日志膨胀和业务写入冲突。
