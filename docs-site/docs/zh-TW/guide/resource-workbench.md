# 原生資源工作台

原生資源工作台（Native Resource Workbench）是 Navop 為擴充功能提供的一類原生介面：擴充功能在 manifest 中宣告資源、集合、表格、詳情頁與操作，宿主以原生 GPUI 渲染出可瀏覽、可操作的工作台，擴充功能不需要自帶 UI。首個以此機制發布的是 Docker 擴充功能。

![擴充功能市集](/images/extension.png)

## 與一般連線擴充功能的差異

- 一般連線擴充功能通常只提供連線表單與一個自訂頁面。
- 資源工作台由宿主統一渲染導覽、集合表格、詳情頁與操作按鈕，擴充功能只宣告資料路徑與操作方法，因此外觀、排序、分頁與互動都跟隨 Navop 主題與設計系統。
- 各操作依 effect 分為唯讀（read）、寫入（write）與破壞性（destructive）：破壞性操作在執行前會彈出確認。

## Docker 工作台

安裝 Docker 擴充功能後，新增 Docker 連線並填寫本機 socket（預設 `unix://~/.docker/run/docker.sock`，也可用 `unix:///var/run/docker.sock`）。工作台提供：

- 引擎總覽：容器、映像、磁碟與執行階段資源用量。
- 容器：清單瀏覽，啟動、停止、重啟與刪除，檢視處理程序與檔案系統變更。
- 映像：映像清單與非同步拉取。
- 日誌：容器日誌檢視器，支援 tail 行數控制。
- 終端：進入容器執行命令的 exec 終端。

刪除容器、停止執行中的服務等操作會影響真實環境，執行前請確認目標容器與影響範圍。

## 權限與自動化

工作台操作透過擴充功能 provider 處理程序執行，並受擴充功能宣告的權限約束（例如存取 `docker.sock`）。在 Public MCP 等自動化通道中，預設只暴露唯讀操作；寫入與破壞性操作仍需人工確認，不會靜默放通。

## 排查順序

1. 確認 Docker 守護程序正在執行，且 socket 路徑正確。
2. 連線失敗時檢查目前使用者是否有權限存取 `docker.sock`。
3. 操作按鈕長時間無回應時，檢查擴充功能 provider 處理程序是否存活；處理程序崩潰後宿主會自動重啟並嘗試恢復連線。
4. 單一擴充功能損壞不會影響其他擴充功能，可在擴充功能管理頁重新載入或解除安裝後重裝。
