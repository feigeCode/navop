# 遠端桌面、串口與伺服器監控

Navop 透過 Provider 擴充連接 RDP 和 VNC，並提供 Serial 串口終端及 SSH 主機監控頁。可用能力取決於平台、擴充版本和遠端系統。

## RDP 與 VNC Provider

先從擴充市場安裝相容的遠端桌面 Provider，再新增 RDP 或 VNC。填寫主機、連接埠、使用者和密碼；RDP 可能還需要 Domain。版本不相容時更新或重新載入擴充，不要任意修改憑證。

在 Windows 上，從連線右鍵功能表開啟獨立視窗時，RDP 會改用系統遠端桌面用戶端 `mstsc.exe` 啟動全螢幕工作階段，更穩定地處理白畫面、焦點和結束問題；主機名稱、IPv4/IPv6 與自訂連接埠會正確傳遞給系統用戶端。內嵌原生 RDP 預設在標籤頁中開啟；非 Windows 平台及 VNC 獨立視窗繼續使用 Navop 內建視窗。

依支援情況設定 SOCKS/HTTP 代理與唯讀模式。唯讀可降低誤輸入，但不取代遠端帳號權限。首次連線核對憑證或主機身分。

## 顯示、輸入與斷線

解析度、剪貼簿、鍵盤配置和輸入行為由 Provider 與平台決定。RDP/VNC 現在使用增量畫面更新，活躍工作階段通常比整幀刷新更順暢；遇到延遲時仍應先降低顯示負載並檢查網路。黑畫面或驗證失敗可能來自會話政策、Domain、憑證或連接埠。

關閉前儲存遠端應用程式內容。中斷連線不一定代表登出，敏感工作階段需按遠端政策鎖定或登出。

## Serial 串口

選擇裝置並設定鮑率、資料位元、停止位元、同位檢查和流量控制，所有參數都需符合硬體。確認串口未被其他程式占用，並使用正確介面與電氣規格。

發送重設、清除或韌體命令前先閱讀設備文件。macOS 對虛擬串口 pty 有限制，應使用支援的實體裝置節點並檢查隱私權限。

## 監控 SSH 主機

「監控」頁會為已儲存的 SSH 主機採集 CPU、記憶體、磁碟分割區與網路狀態。監控預設關閉，需按連線開啟：在主機卡片上打開「資源監控」開關，或從該主機的入口開始監控。只有已開啟的主機會維持長連線採樣；同一個開關也決定首頁連線列表是否顯示該主機的資源佔用。

頁面可設定每 5、15 或 30 秒刷新，支援搜尋主機、重新連線並刷新全部監控，並以資源卡片呈現趨勢。主機提供 GPU 或 NPU 時會出現對應視圖。若主機需要互動式憑證（keyboard-interactive 或 TOTP），先在終端連線一次，或先儲存憑證；重新連線時監控頁也能自動應答這些提示。

採樣只在目前的 SSH 工作階段內執行，不會在遠端主機寫入任何檔案。舊版曾部署 `~/.onetcli-monitor` helper，該目錄現在只會盡力清理，已不再需要。終端側邊欄的「伺服器監控」面板使用同一個採集器，只作用於目前工作階段。

採樣會使用少量資源，程序與網路資訊也可能屬於敏感維運資料。趨勢只能輔助診斷，不能取代正式告警和稽核系統。

## 更新與移除

版本不符時更新 Provider。移除 Provider 只會讓對應連線暫時無法開啟，不會刪除遠端系統。要停止監控某台主機，關閉它的資源監控開關，再依組織政策確認沒有殘留的 helper 或背景工作階段。

代理、唯讀和監控都不會繞過遠端權限。排查時先分別驗證網路、擴充、帳號和遠端服務。
