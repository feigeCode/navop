# 遠端桌面、串口與伺服器監控

Navop 透過 Provider 擴充連接 RDP 和 VNC，並提供 Serial 串口終端及 SSH 伺服器監控。可用能力取決於平台、擴充版本和遠端系統。

## RDP 與 VNC Provider

先從擴充市場安裝相容的遠端桌面 Provider，再新增 RDP 或 VNC。填寫主機、連接埠、使用者和密碼；RDP 可能還需要 Domain。版本不相容時更新或重新載入擴充，不要任意修改憑證。

依支援情況設定 SOCKS/HTTP 代理與唯讀模式。唯讀可降低誤輸入，但不取代遠端帳號權限。首次連線核對憑證或主機身分。

## 顯示、輸入與斷線

解析度、剪貼簿、鍵盤配置和輸入行為由 Provider 與平台決定。RDP/VNC 現在使用增量畫面更新，活躍工作階段通常比整幀刷新更順暢；遇到延遲時仍應先降低顯示負載並檢查網路。黑畫面或驗證失敗可能來自會話政策、Domain、憑證或連接埠。

關閉前儲存遠端應用程式內容。中斷連線不一定代表登出，敏感工作階段需按遠端政策鎖定或登出。

## Serial 串口

選擇裝置並設定鮑率、資料位元、停止位元、同位檢查和流量控制，所有參數都需符合硬體。確認串口未被其他程式占用，並使用正確介面與電氣規格。

發送重設、清除或韌體命令前先閱讀設備文件。macOS 對虛擬串口 pty 有限制，應使用支援的實體裝置節點並檢查隱私權限。

## SSH 伺服器監控

監控頁顯示 CPU、記憶體、磁碟、網路和程序趨勢。經明確確認後，Navop 會部署 `~/.onetcli-monitor` helper；受管理伺服器需先取得管理員同意與執行權限。

採樣會使用少量資源，程序和網路資訊也可能敏感。趨勢只能輔助診斷，不能取代正式告警和稽核系統。

## 更新與移除

版本不符時更新 Provider 或 helper。移除 Provider 只會讓對應連線暫時無法開啟，不會刪除遠端系統。停止監控時確認遠端 helper 是否仍在執行並依政策清理。

代理、唯讀和監控都不會繞過遠端權限。排查時先分別驗證網路、擴充、帳號和遠端服務。
