# Schema、表設計與比較同步

結構工具包含物件瀏覽、表設計器、DDL、ER 圖、Schema Compare 和 Data Compare。它們可能產生 DROP、ALTER、INSERT、UPDATE 或 DELETE，所有自動計畫都必須人工審閱。

## 瀏覽資料庫物件

展開資料庫和 Schema，查看資料表、檢視及其他支援物件。資料表頁可顯示欄位、類型、預設值、可空性、主鍵、索引和 DDL。可見性受權限、上下文與 Schema 過濾共同影響。

變更前先重新整理，避免舊標籤未反映其他使用者或工具的最新修改。

## 使用表設計器

新增或修改欄位、索引，以及支援的引擎、字元集和排序規則。縮小類型或改變可空性前確認既有資料可轉換；建立唯一索引前先清除重複資料。

切換 SQL/DDL 預覽檢查產生語句。Navop 會提示 DROP 等破壞性操作，但無法理解所有業務影響。遷移應先在測試庫驗證並準備回復或還原方案。

## 建立 ER 圖

ER 圖顯示資料表及元資料定義的關係。沒有外鍵的邏輯關係可能不會出現，因此仍需結合應用程式知識。大型 Schema 應先選擇相關物件，減少雜訊。

ER 圖是結構輔助，不是即時資料流、權限或稽核模型。

## Schema Compare

選擇來源與目標連線，先確認方向，再查看新增、修改與缺少的物件。只勾選要同步的內容，檢查相依順序與不支援特性。同步 SQL 可在執行前編輯。

DROP、類型縮小、索引重建和大型 ALTER 需要備份與維護計畫。不同資料庫產品間還需人工處理類型與語法。

## Data Compare

Data Compare 以可用鍵比對列，統計需要的 INSERT、UPDATE 和 DELETE。缺少穩定主鍵或唯一鍵時，結果可能不可靠；先檢查鍵、篩選範圍與資料量。

審閱可編輯 SQL、交易與遇錯停止策略。執行日誌用來定位錯誤，完成後仍須查詢目標驗證。大型同步先用樣本或副本演練。
