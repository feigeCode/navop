# 疑難排解與問題報告

排查時一次只改一個變數，先判斷屬於網路、驗證、權限、驅動、擴充、用戶端狀態或遠端服務。記錄平台、Navop 版本、連線類型、時間與最小重現步驟，不要用管理員帳號掩蓋設定錯誤。

## 資料庫、Redis 與 MongoDB

SQL 資料庫依序檢查 DNS、主機、連接埠、防火牆、帳號、資料庫/Schema、TLS、代理、SSH 通道、驅動和伺服器版本。SQL 錯誤縮小到單一語句並處理提交或回復；物件不可見時檢查權限和 Schema 過濾。

Redis 確認單機、Sentinel、Cluster 模式與節點可達。MongoDB 檢查連線字串、驗證資料庫、TLS、拓撲探索和 BSON 型別。不要用 FLUSH、刪除集合或關閉憑證驗證當作診斷捷徑。

## SSH、終端與 SFTP

檢查指紋、使用者、密碼/私鑰、檔案權限、SSH Agent、MFA、代理和伺服器日誌。SSH 可登入但 SFTP 失敗時，再查子系統、目錄權限和磁碟。傳輸中斷後比較遠端大小，編輯衝突保留雙方內容。

終端亂碼可能來自遠端 locale、字型或編碼。轉發問題要區分本機連接埠占用、SSH 中斷、目標拒絕和監聽位址。

## 擴充、遠端桌面與串口

功能缺少時確認擴充已安裝、啟用並與平台及 Navop 版本相容，再重新載入並查日誌。驅動、ACP Agent 和遠端桌面 Provider 可各自失敗，升級回歸應記錄新舊版本。

RDP/VNC 問題可能涉及 Provider、Domain、憑證、會話政策或網路。Serial 亂碼則核對裝置、鮑率、資料位元、停止位元、同位檢查和流量控制。

## AI、ACP 與 Public MCP

模型失敗時檢查 Provider、API key、base URL、模型、網路與額度。工具缺少可能來自模式、資源或權限；ACP 授權不會移除 Public MCP 的審批。

Public MCP 檢查 Navop 執行狀態、服務模式、Node.js 20+、`npx`、用戶端設定、discovery 權限、Tool Exposure 和即時 Schema。endpoint 重啟後重新連線，不要猜測資源 ID。

## 同步、加密與更新

同步失敗檢查帳號、網路、主密鑰、團隊密鑰、角色、版本和未解衝突。官網無法恢復遺失的主密鑰；輪換期間避免批次並行編輯。

更新失敗時確認磁碟、安裝包架構、系統安全政策和擴充相容性，回退前備份本機資料。

## 提交遮蔽報告

從設定找到日誌路徑，只附發生時間附近的最小片段，並說明預期、實際結果和可重複步驟。盡量使用虛構主機、示例 Schema 與最小 SQL。

移除密碼、API key、Token、主密鑰、SSH/憑證私鑰、完整連線字串、內網位址、個人資料和業務結果。畫面也要遮蔽標籤、歷史和路徑。若涉及資料破壞，停止重試並保存備份、日誌和伺服器稽核證據。
