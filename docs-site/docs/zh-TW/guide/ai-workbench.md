# AI 工作台、Agent 與 ACP

AI 工作台把模型對話放在真實資料庫、終端、檔案和 Notes 旁。模型輸出可能錯誤，工具呼叫則可能執行真實操作；應依風險選擇 Ask、Plan 或 Auto，並保留人工驗證。

## 設定 LLM Provider

在設定新增 Provider，填寫名稱、API key、base URL、API version 等欄位，再載入模型或加入自訂模型。可啟用、停用、編輯、刪除並設定預設 Provider。企業代理或相容介面要先確認協定與資料政策。

API key 不得貼入對話、畫面或報告。修改 base URL 前確認目標可信。歷史訊息數、temperature 和 max tokens 可依上下文、成本與穩定性調整。

## Ask、Plan 與 Auto

Ask 適合問答、解釋和草稿；Plan 先整理步驟供審閱；Auto 可在授權範圍內繼續更多操作。正式資料庫、終端寫入或檔案覆寫優先使用 Ask 或 Plan。

模型產生的 SQL 和命令必須閱讀後再執行，解釋也要和真實 Schema、樣本及伺服器輸出交叉檢查。

## 資源、附件與 Skill

使用 `@` 引用連線、查詢結果、檔案或資源池內容，也可附加圖片。只提供解決問題所需的最少資料，名稱、結果列和畫面都可能敏感。

Skill 提供特定工作流程與規則。Navop Skill 能讓 Codex 等終端型 AI Agent 透過 `navop ... --json` 按需操作 Navop 資源，只在任務需要時探索命令與 Schema，不必在每輪上下文攜帶完整 MCP 工具目錄，因此可減少重複工具定義帶來的 Token 開銷。CLI 底層仍連接 Navop 的本機 Public MCP runtime，不能繞過 Tool Exposure、權限或審批。匯入前閱讀來源和權限，更新後重新評估行為。

## 會話、任務與審批

可新增、重新命名、封存和刪除對話或任務。封存只用於整理，不保證外部模型服務已刪除接收過的資料。工具頁會顯示呼叫、計畫和審批，允許前核對工具、資源、參數與副作用。

Agent 可使用計畫或子代理，但結果仍須驗證。長任務執行前重新檢查連線與檔案狀態。

## ACP 與 HTML 預覽

ACP 擴充接入外部 Agent，可能要求登入和權限；外部管理的任務不一定由 Navop 保存。即使 ACP 已授權，Public MCP 呼叫仍可能再次要求 Navop 審批，這是預期的宿主安全邊界。

HTML 程式碼區塊可複製、下載、在瀏覽器開啟或應用程式內預覽。WebView 不可用時保留原始碼。未知 HTML 可能載入外部資源或執行腳本，預覽不是絕對沙箱。
