# 快速開始

Navop 把資料庫、Redis、MongoDB、SSH、SFTP、終端、遠端桌面、串口、Notes、AI 與加密團隊同步放在同一個原生工作區。第一次使用不必設定所有功能，先完成一項真實任務，再依本手冊逐步擴充。

## 五分鐘完成第一項任務

從 [GitHub Releases](https://github.com/feigeCode/navop/releases) 下載與作業系統及架構相符的版本。啟動後選擇「新增連線」，建立資料庫或 SSH 連線，填寫位址、連接埠與驗證資料，先測試再儲存。

- 資料庫使用者可展開 Schema 與資料表，開啟 SQL 編輯器並執行唯讀查詢。
- 伺服器使用者可開啟 SSH 終端，先執行 `pwd` 等低風險命令，再進入 SFTP 瀏覽目錄。
- 本機工作可直接使用 Terminal、Notes，或透過系統關聯開啟 `.db`、`.duckdb` 與 `.md`。

## 認識完整產品地圖

首頁管理連線和工作區；資料庫區域包含 SQL、資料表資料、表設計、ER 圖、匯入匯出和結構或資料比較；Redis 與 MongoDB 有各自的瀏覽器、編輯器與診斷頁。SSH 工作區結合分割終端、歷史、快捷命令、SFTP、遠端編輯和伺服器監控。RDP、VNC、Serial 與 Port Forwarding 也從新增連線進入。

Notes 提供本機 Markdown 的唯讀預覽與原始碼編輯。AI 工作台可設定 Provider，並選擇 Ask、Plan 或 Auto。Codex 等可執行終端命令的 AI Agent 可以安裝 Navop Skill，透過 `navop` 按需操作資源，不必在每輪攜帶完整 MCP 工具目錄，從而減少重複上下文和 Token 開銷。CLI 仍需啟用 Public MCP，並遵循 Tool Exposure、權限與審批。擴充市場則提供資料庫驅動、ACP Agent、連線匯入、遠端桌面和語言。

## 建議的學習順序

先用測試環境熟悉唯讀操作，再設定資料庫與終端偏好，接著嘗試傳輸、遠端編輯與 AI。只有需要跨裝置或多人協作時，才登入並啟用個人同步或團隊。將正式、測試和本機資源分到名稱清楚的工作區。

執行寫入、刪除、DDL、批次同步、檔案覆寫或廣播輸入前，重新確認環境、選取範圍與交易策略，並優先使用備份、測試資料和最小權限帳號。

## 保護憑證與自動化

主密鑰會在本機加密資料庫密碼、SSH 私鑰等敏感資料；同步服務保存的是裝置產生的密文，官網無法恢復遺失的主密鑰。團隊密鑰也只以受保護形式保存在成員裝置。

AI 與 Public MCP 工具可能執行真實操作。首次使用採保守權限，只開放當前任務所需工具並閱讀每次審批。不要公開密碼、Token、主密鑰、私鑰、完整日誌或未遮蔽的畫面。
