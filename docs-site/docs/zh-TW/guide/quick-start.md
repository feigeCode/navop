# 快速開始

Navop 現在有三個應用程式，共用同一套原生核心：完整版 **Navop**、遠端維運 **Navop Shell**、資料工具 **Navop Data**。第一次使用不必一次設定所有能力：先依下表選一個應用程式，完成一個真實任務，再照本手冊繼續擴充。

![Navop 工作區總覽](/images/app.png)

圖中的首頁是連線與工作區的入口。資料庫、SSH/SFTP、Redis、MongoDB、終端機與遠端桌面連線都從這裡建立，開啟連線後才會出現對應的編輯器、瀏覽器或終端機分頁。

## 該選哪個應用程式

| 你的主要工作 | 建議應用程式 |
| --- | --- |
| 資料庫和伺服器都要管，或需要 ER 圖、資料搬移、監控、檔案關聯 | **Navop**（完整版） |
| 主要是 SSH 登入伺服器、SFTP 傳檔、連接埠轉送、RDP/VNC 遠端桌面、串口/Telnet | **Navop Shell**（遠端維運） |
| 主要是連資料庫寫 SQL、管理 Redis/MongoDB、看 ER 圖、搬移資料 | **Navop Data**（資料工具） |

三個應用程式共用 AI、Notes、團隊同步、擴充商店、主題、快速鍵、tab 還原、系統匣、單一執行個體與自動更新，同版本發布且可以並排安裝；資料目錄與鑰匙圈各自獨立。不確定就先裝完整版 Navop，它的能力最完整，之後仍可並排安裝獨立產品。

## 五分鐘完成第一個任務

三個應用程式都從[官網下載中心](https://navop.dev/zh-TW/extensions)下載對應安裝檔，安裝方式見[安裝與更新](./install-update)。

### 使用 Navop（完整版）

1. 啟動 Navop，在首頁選擇「新增連線」，建立資料庫或 SSH 連線，填寫位址、連接埠與認證資訊，先執行「測試連線」。
2. 測試通過後開啟連線：資料庫連線會進入資料庫工作區，展開 Schema 與資料表，在 SQL 編輯器執行一筆唯讀查詢；SSH 連線會進入終端機工作區，執行 `pwd`、`whoami` 等低風險指令，再進入 SFTP 查看遠端目錄。
3. 需要本機工作時，直接開啟終端機或 Notes；完整版 Navop 還會接管 `.db`、`.duckdb`、`.md` 與 `.cast` 檔案關聯。

### 使用 Navop Shell（遠端維運）

1. 啟動 Navop Shell，從首頁「新增連線」建立 SSH/SFTP、終端機、RDP/VNC、串口/Telnet 或連接埠轉送。
2. 先測試連線，再開啟 SSH 終端機執行 `pwd`、`whoami` 等指令，或進入 SFTP 瀏覽遠端目錄。
3. 需要圖形工作階段時，先從擴充商店安裝遠端桌面 Provider，再建立 RDP 或 VNC 連線；需要通道時，從已儲存的 SSH 連線建立連接埠轉送。

### 使用 Navop Data（資料工具）

1. 啟動 Navop Data，建立資料庫、Redis 或 MongoDB 連線，填寫位址、連接埠與認證資訊後先測試。
2. 資料庫連線會進入 SQL 工作區，展開 Schema 與資料表並執行一筆唯讀查詢；Redis 與 MongoDB 分別開啟各自的瀏覽器與診斷入口。
3. 需要梳理資料表關聯或搬移資料時，開啟 ER 圖或資料搬移；這兩個入口只會出現在資料工作區。

## 認識產品地圖

**完整版 Navop** 涵蓋資料庫、Redis、MongoDB、SSH/SFTP、本機與遠端終端機、連接埠轉送、遠端桌面、串口/Telnet、SQL 編輯器、ER 圖、資料搬移、監控、Notes、AI 工作台、團隊同步、擴充商店與 Public MCP。首頁負責管理連線與工作區；資料庫區域涵蓋 SQL、資料表資料、資料表設計、ER 圖、匯入匯出與比對同步；SSH 工作區包含終端機、分割窗格、快速指令、SFTP、遠端編輯與伺服器監控。

**Navop Shell** 保留遠端維運相關的工作區：SSH/SFTP、本機與遠端終端機、連接埠轉送、RDP/VNC 遠端桌面、串口/Telnet，並共用 AI、Notes、團隊與擴充體系。

**Navop Data** 保留資料工作相關的工作區：SQL 工作區、Redis、MongoDB、ER 圖、資料搬移，並共用 AI、Notes、團隊與擴充體系。

三個應用程式共用主題、快速鍵、tab 還原、系統匣、單一執行個體、自動更新與 Public MCP。Public MCP 依應用程式個別探索、個別授權：`navop`、`navop-shell`、`navop-data` 各自只提供該應用程式當下可用的工具，不要假設某個應用程式的 manifest 能操作另一個應用程式。

Notes 提供本機 Markdown 唯讀預覽與原始碼編輯。AI 工作台在三個應用程式一致，可設定模型 Provider，並以 Ask、Plan 或 Auto 模式圍繞真實資源工作。對於 Codex 等可執行終端機指令的 AI Agent，可安裝 Navop Skill，透過 `navop` 按需操作資源，減少每輪攜帶完整 MCP 工具定義的上下文與 Token 開銷。CLI 仍要求啟用對應應用程式的 Public MCP，並遵循 Tool Exposure、權限等級與核准策略。擴充商店用於安裝資料庫驅動、ACP Agent、連線匯入、遠端桌面與語言套件。

## 建議的上手順序

先建立個人連線並熟悉唯讀操作，再設定終端機與資料庫偏好；之後嘗試匯入匯出、遠端編輯或 AI。只有確實需要跨裝置或多人協作時，才啟用個人同步或團隊空間（團隊、成員與團隊金鑰都在應用程式的「團隊」頁管理）。團隊的 Owner、Admin 與 Member 權限不同，應先由管理員完成團隊金鑰初始化。

建議為正式、測試與本機環境建立不同工作區，並替連線取清楚的名稱。執行寫入 SQL、批次刪除 Key、清空資料表、覆寫遠端檔案、同步差異或廣播輸入前，重新確認目前環境、選取範圍與交易策略。

## 安全與資料原則

連線密碼、SSH 私鑰等敏感資訊由主密鑰在本機加密。啟用同步後，雲端保存的是本機加密產生的密文；主密鑰遺失無法由官網復原。團隊金鑰也只以加密形式保存在成員裝置上。不要把正式環境憑證、主密鑰、完整日誌或未去識別化的截圖貼到公開管道。

三個應用程式各自維護資料目錄與鑰匙圈；即使並排安裝，也不會共用同一份連線密文。備份、搬移或還原時請依應用程式分別處理，不要把兩個應用程式的目錄混在一起。

Public MCP 與 AI 工具可能執行真實操作。首次使用時選擇較保守的權限等級，只開放目前任務需要的工具，逐次閱讀核准內容。任何刪除、覆寫、清空、DDL、批次同步與停止轉送操作都應先確認影響範圍，並優先在想得到可回復的環境驗證。

## 建議的第一個可重現任務

首次啟動時，應用程式會在本機資料目錄初始化 `Demo Orders (SQLite)` 示範資料庫。這個資料庫只用於熟悉介面，不連線網路，也不含真實業務資料；在 Navop 與 Navop Data 的資料庫工作區中可以直接開啟。

1. 在首頁找到 `Demo Orders (SQLite)`，開啟資料庫工作區。
2. 展開 Schema 與資料表，先開啟 `customers` 或 `products` 查看資料。
3. 新增 SQL 查詢，執行以下唯讀語句：

```sql
SELECT status, COUNT(*) AS order_count
FROM orders
GROUP BY status
ORDER BY order_count DESC;
```

4. 回到資料表資料頁，分頁瀏覽一張資料表，並開啟一筆記錄的大文字或 JSON 編輯器。
5. 關閉查詢與資料頁，保留連線卡片，繼續閱讀資料庫連線或 SQL 編輯器章節。

如果首頁沒有示範資料庫，先確認應用程式完成過首次啟動初始化；也可以直接從[官網下載中心](https://navop.dev/zh-TW/extensions)下載目前穩定版後重新啟動。不要把示範資料庫當作正式資料備份或同步來源。

## 完成檢查

- [ ] 知道自己用的是 Navop、Navop Shell 還是 Navop Data，以及它與另外兩個應用程式的分工。
- [ ] 能在首頁找到一個連線，並區分連線名稱、類型與環境。
- [ ] 能開啟資料庫物件或 SSH 終端機。
- [ ] 能執行一筆唯讀 SQL，或在終端機執行 `pwd`、`whoami`。
- [ ] 知道關閉分頁不會刪除連線，刪除連線也不會直接刪除遠端資料庫。
- [ ] 知道寫入 SQL、刪除 Key、覆寫檔案與廣播輸入前要重新確認目標。
