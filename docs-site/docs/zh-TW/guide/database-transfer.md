# 資料庫匯入、匯出與 SQL 檔案

傳輸工具可匯入分隔文字、匯出資料表或查詢結果、產生 SQL dump，並執行現有 SQL 檔。開始前先確認來源格式、目標表、編碼、交易策略和復原方案。

## 匯入 CSV 與分隔文字

選擇目標表和檔案後，設定字元編碼、欄位分隔符、文字包圍符、跳脫規則和是否包含標題列。預覽欄位對應，確認來源值符合資料庫類型與可空性。日期、小數、布林、`NULL` 和空字串在不同系統中可能不同，先用少量樣本驗證。

支援的資料庫可用交易讓批次匯入保持整體一致。「遇錯停止」適合要求一致性的任務，「遇錯繼續」可收集壞列，但完成後必須檢查錯誤。超大檔案應分批並監控日誌、磁碟和逾時。

## 清表與不可逆風險

「匯入前清表」會先清除目標表既有資料，通常不可恢復。只有確認備份、環境、外鍵相依和還原步驟後才能啟用，測試預覽不應勾選。

匯入失敗不代表完全沒有寫入，實際結果取決於交易、批次和錯誤策略。重試前先查詢目標列數，避免重複資料。

## 匯出資料

從資料表或 SQL 結果選擇欄位、列範圍和格式，並確認編碼、分隔符、標題、換行、日期與 NULL 表示。CSV 適合交換，XLSX 適合人工檢視，SQL 適合可審閱的插入語句。

試算表可能自動轉換長識別碼與日期。匯出檔離開資料庫權限邊界，含敏感內容時必須受控保存和刪除。

## SQL dump

可選只匯出結構、只匯出資料，或結構與資料。組合 dump 仍須考慮物件順序、外鍵、觸發器、序列、字元集和方言。

先檢查產出並在空白測試庫還原。不同資料庫產品間通常需要人工轉換類型和語法，不能假設直接相容。

## 執行 SQL 檔案

確認連線、資料庫或 Schema、檔案編碼、交易與錯誤策略。大型腳本先閱讀開頭和結尾，檢查 DROP、TRUNCATE、權限變更和環境專用語句。

使用執行日誌定位失敗。取消或斷線後重新確認已提交範圍，並以物件數、列數和業務檢查證明結果，不要只看進度條。
