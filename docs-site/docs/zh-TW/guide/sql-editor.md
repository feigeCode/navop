# SQL 編輯器與交易

SQL 編輯器用來編寫、儲存、解釋與執行語句。執行範圍、目前資料庫及交易模式決定影響面；正式寫入前必須重新確認連線、Schema 和選取內容。

## 建立與儲存查詢

從資料庫工作區新增查詢，選擇目前資料庫或 Schema 並輸入 SQL。查詢可儲存、重新命名和再次開啟。自動儲存只保存編輯內容，不會自動執行，也不能取代版本控制與備份。

格式化或壓縮只改變排版，不代表語意正確。複雜遷移腳本應保留原稿並先在測試庫驗證。

## 選擇執行範圍

可執行選取 SQL、游標所在語句或全部內容。有選取時先檢查起訖位置；無選取時把游標放在目標語句。只有完整審閱的腳本才適合「全部執行」，草稿可能混有範例或臨時 DELETE。

結果區顯示資料、影響列數或錯誤。結果分頁可獨立切換，並在穩定的可視區域內滾動，即使是長結果或多語句執行也不會把捲軸推離畫面。最大列數限制可避免巨大結果耗盡記憶體；完整資料應使用匯出，而不是無限制提高預覽值。

## EXPLAIN 與效能

對支援的查詢使用 EXPLAIN 查看掃描、索引、連接順序和預估成本。不同資料庫語法與欄位不同；含 ANALYZE 的變體可能實際執行查詢，使用前先確認負載與副作用。

保留原 SQL 和基準，不要只因成本數字就刪除索引或更改正式邏輯，資料分布、快取和併發都會影響結果。

## 自動與手動交易

自動模式依驅動規則提交。手動交易把多個修改保留到明確提交或回復，未提交內容可能持有鎖並阻塞其他工作階段。

切換資料庫、Schema 或關閉編輯器前，Navop 會要求結束手動交易。提交讓修改永久生效，回復撤銷尚未提交內容。斷線後應重新查詢確認狀態，不要自行假設結果。

## 安全處理錯誤

語法、權限、限制或逾時錯誤應縮小到單一語句，並閱讀伺服器訊息。交易狀態不明時不要反覆執行。UPDATE 或 DELETE 前可先用相同 WHERE 執行 SELECT 核對目標。

分享 SQL 或問題報告前移除密碼、Token、個人資料與正式環境字面值。
